# Skyfield Overwatch Unit

Discord-бот сообщества Skyfield. Python 3.12, discord.py, SQLite.
Оранжево-чёрное оформление, предоставленный логотип в assets/logo.png.

## Что умеет

- Счёт от 1 до 1 000 000 000 000. «2..», «3...», «5-3», скобки, +, -, *, /, %.
  Вычисления точные, без eval и выполнения кода. Один игрок не ходит подряд.
  Неверное число, текст, вложение без числа или повторный ход сбрасывают счёт.
  Рекорд сохраняется. После достижения цели новый раунд запускает администратор.
- Русские слова по последней букве. Существительные в начальной форме,
  без имён собственных и повторов. Ё=Е; конечные Ь/Ъ/Ы пропускаются.
  Участники чередуются, ошибка не обнуляет раунд. Проверка по словарю pymorphy3;
  редкие слова, которых нет в словаре, могут быть отклонены.
- «Жду сервер день N»: личная ежедневная серия, календарные дни Europe/Moscow.
  Пропуск дня — следующая отметка с 1. Общая статистика и лучший результат сохраняются.
- Досье, описание о себе, +rep/-rep, восемь таблиц лидеров.
  Один голос репутации любому участнику раз в 24 часа, без оценки себя и ботов.
- Очки за первого приглашённого участника: по умолчанию 10, настраивает администратор.
  Очки и приглашения видны в профиле и /top. Выход не отнимает очки;
  повторный вход того же аккаунта не приносит новые. Магазина/траты очков пока нет.
- Постоянная панель с кнопками; её кнопки продолжают работать после перезапуска.
- Змейка и одиночный Pong в личном ответе Discord. Один клик — один шаг.
  Pong: передвигай нижнюю ракетку и отражай мяч; верхняя стенка отражает его обратно.
  Это пошаговые игры, не realtime. Тайм-аут 3 минуты бездействия.
  Личные рекорды сохраняются при завершении, проигрыше и тайм-ауте.
  При аварийном перезапуске активные партии теряются; сохранённые рекорды остаются.

## 1. Создай приложение Discord

1. Открой https://discord.com/developers/applications и создай New Application:
   **Skyfield Overwatch Unit**.
2. На странице Bot установи имя и аватар из assets/logo.png.
3. Скопируй токен Bot в свой локальный .env. Не публикуй его и не присылай в чат.
4. В Bot → Privileged Gateway Intents включи **Message Content Intent**
   и **Server Members Intent**. Presence Intent не нужен.
5. В OAuth2 → URL Generator выбери `bot` и `applications.commands`.
   Права: View Channels, Send Messages, Read Message History, Add Reactions,
   Embed Links, Attach Files и **Manage Server** (для списка приглашений).
   Administrator не нужен. Открой полученную ссылку и добавь бота на сервер.
6. Убедись, что права в игровых каналах не запрещены отдельными настройками канала.

## 2. Локальный запуск

Установи Python 3.12. Открой терминал в папке проекта.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
# Открой .env и впиши DISCORD_TOKEN. GUILD_ID — ID твоего сервера.
.\.venv\Scripts\python bot.py
```

Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# Отредактируй .env
.venv/bin/python bot.py
```

GUILD_ID можно взять через режим разработчика Discord → правой кнопкой по серверу →
«Копировать ID». С GUILD_ID команды регистрируются только для этого сервера.
Без него — глобально; появление глобальных команд может занять время.
Не переключай режим регистрации без необходимости: Discord может сохранять команды
из предыдущего режима, и в меню появятся дубликаты.

## 3. Настрой всё командами администратора

Нужны пять разных текстовых каналов, например:

| Назначение | Канал | Аргумент /setup |
|---|---|---|
| Общий счёт | #счёт | count |
| Слова | #слова | words |
| Дневные серии | #жду-сервер | wait |
| Команды и панель | #overwatch-unit | commands_channel |
| Сообщения о приглашениях | #приглашения | invites |

Вызови `/setup`, выбери все пять каналов и `invite_points` (например 10).
Настройка сохраняется в базе, её можно повторить для изменения каналов/награды.
Новая награда применяется к будущим приглашениям, старые очки не пересчитываются.
Команды обычных участников разрешены в канале commands_channel.
Администраторы с правом «Управлять сервером» могут настраивать бота из любого канала.

В канале команд вызови `/panel` — появится панель с логотипом и кнопками.
Старую панель после переноса канала можно удалить вручную.
Для сброса игры: `/reset game:Счёт confirm:True` или «Слова».
Личные достижения и общий рекорд счёта при этом не удаляются.

## Команды

| Команда | Действие |
|---|---|
| /setup | Каналы + награда за приглашение (администратор) |
| /invites_sync | Обновить снимок приглашений (администратор) |
| /panel | Опубликовать панель (администратор) |
| /reset | Новый раунд счёта/слов (администратор) |
| /profile [member] | Своё/чужое досье, очки, репутация, рекорды |
| /bio text | Текст о себе, до 250 символов |
| /rep member value | +rep или -rep |
| /stats | Общий прогресс и назначенные каналы |
| /top category | Лидеры: очки, приглашения, репутация, счёт, слова, серия, Snake, Pong |
| /snake | Змейка |
| /pong | Одиночный Pong |
| /help | Правила прямо в Discord |

Репутация выдаётся через /rep с выбором +rep/-rep, а не произвольными сообщениями.
Числа, слова и дневные отметки отправляются обычными сообщениями в назначенных каналах.
Редактирование/удаление сообщения не отменяет уже обработанный ход.

## Как считается приглашение

Discord не передаёт пригласившего в событии входа. Бот сравнивает счётчики
использований ссылок до/после входа. Используй обычные бессрочные приглашения
без лимита использований, созданные самим участником.
После создания новых ссылок администратор должен выполнить `/invites_sync`
до входа участников. Если у бота есть дополнительное право Manage Channels,
события создания ссылок могут обновлять снимок автоматически.

Очки выдаются только когда ровно одна известная ссылка использована ровно один раз.
Одновременные входы, исчезнувшие одноразовые ссылки, vanity/discovery, отсутствие
прав, вход во время простоя или неполный снимок могут оставить источник неизвестным.
В таком случае в канале будет уведомление без начисления; автоматической догадки нет.
Это консервативный учёт, не абсолютное доказательство источника входа.
При старте существующие участники добавляются в список уже виденных.
Бот не может распознать разные аккаунты одного человека: защита от повторного входа
не является полной защитой от накрутки альт-аккаунтами.

## Хостинг: где держать бота 24/7

### Вариант A — VPS / Timeweb Cloud

https://timeweb.cloud/services/vds-vps

Рекомендуемая стартовая конфигурация для небольшого сообщества: Ubuntu, 1 vCPU,
1 ГБ RAM, 10–15 ГБ диска. Выбирай локацию с доступом к Discord API/Gateway.
Цена зависит от региона и тарифа — смотри актуальную при заказе.
Нужен VPS с постоянно работающим процессом, не обычный хостинг PHP-сайтов.

Установи Docker Engine и Compose по официальной инструкции:
https://docs.docker.com/engine/install/ubuntu/

Загрузи папку проекта на VPS, создай .env из .env.example, впиши токен и ID сервера:

```bash
docker compose up -d --build
docker compose logs -f --tail=100
```

Перезапуск: `docker compose restart`. Обновление файлов: `docker compose up -d --build`.
Compose сохраняет SQLite в именованном томе `skyfield-data` и перезапускает процесс.
Не используй `docker compose down -v`: ключ -v удаляет том с прогрессом.
Входящие порты открывать не нужно: бот сам подключается к Discord.

### Вариант B — Railway

https://railway.com/pricing

Hobby: минимум $5/месяц, включает $5 использования, превышение оплачивается отдельно.
Тариф проверен 9 ноября 2026; перед заказом проверь текущую страницу.

1. Создай приватный GitHub-репозиторий с файлами проекта, без .env и базы.
2. В Railway создай проект из этого репозитория. Dockerfile уже включён.
3. В Variables добавь DISCORD_TOKEN, GUILD_ID, DATABASE_PATH=/app/data/skyfield.sqlite3.
4. Добавь постоянный Volume с точкой монтирования **/app/data**.
5. Оставь **одну реплику**, отключи Serverless/sleep для постоянно работающего бота.
6. Выполни deploy. В журнале должно появиться «Skyfield online».

Без Volume база будет потеряна при пересоздании контейнера.
Не запускай два экземпляра с одним токеном: это приводит к повторной обработке событий.
Публичный веб-домен и HTTP healthcheck этому Gateway-боту не требуются.

## Данные и резервное копирование

SQLite хранит ID серверов/участников, настройки каналов, достижения, описание о себе,
последнее время голосования, список использованных слов и уже виденных участников.
Токен не записывается в базу. Текст произвольных сообщений не архивируется.
Для небольшого/среднего сообщества используется одна JSON-запись состояния на сервер.
На очень больших серверах потребуется нормализованная БД и отдельная очередь событий.

Для резервной копии Docker-версии:

```bash
docker compose exec overwatch python -c "import sqlite3; a=sqlite3.connect('/app/data/skyfield.sqlite3'); b=sqlite3.connect('/app/data/backup.sqlite3'); a.backup(b); b.close(); a.close()"
docker compose cp overwatch:/app/data/backup.sqlite3 ./skyfield-backup.sqlite3
```

Для восстановления останови бота и замени основной файл базы копией; удаляй старые
-wal/-shm только при остановленном процессе. Не удаляй рабочий том целиком.

## Проверка перед открытием участникам

```bash
python -m unittest discover -s tests -v
```

Автотесты проверяют арифметику, сбросы, цель, серии, слова, репутацию, транзакции,
сохранение/изоляцию серверов, приглашения, столкновения змейки, Pong и тайм-ауты.
Бот импортирован с установленными зависимостями; команды создаются без токена.
Живое подключение не проверялось: для него нужен токен владельца сервера.
Docker-конфигурация подготовлена, но контейнер здесь не запускался.

На тестовом Discord-сервере проверь /setup и /panel, ходы с двух аккаунтов,
отказ в /setup обычному участнику, начисление по новой постоянной ссылке,
повторный вход без очков и сохранение прогресса после перезапуска.
